# Round 8: record a game's music into FL Studio (SNES first) — brief for the agents

Date: 2026-10-17. Written from the user's request and their answers to the workshop questions. Read `docs/projects/round5-brief.md` (hard rules, traps), `docs/projects/round6-runaway.md` (the S-DSP write log and the notes it already yields), `docs/projects/round6-presets.md` (presets, the Presets chip, direct mode with no ROM), `docs/projects/round6-imodel.md` (the instrument model) and `docs/projects/round7-midi.md` (Test MIDI export, if merged) first.

## The user's vision, in their words (summarised)

"Do Instrument Runaway to freeze the game and take control of the instruments. Then start a **recording session** which interfaces with FL Studio: resume emulation and have **all the instruments firing in the emulation turn into replayable data in FL Studio, mapped on the piano roll**. With the instruments ripped from the emulator and a recording of them playing in the game, we have all the data for **transcribing music corruptions into FL Studio**: corrupting the instruments is not everything that makes a corruption, the song replay (how the sound chip is driven) is the rest, and we need to capture it. Then we can modify it, clean it, maybe shove it back into a ROM later (not now). This feature: **record the data going through the instruments and dump it into FL Studio, to be replayed through BrokenNes in direct mode, without the game running in the background.**" Prototype on the **SNES**, then extend to the other consoles. The user expects this to be hard and wants it workshopped.

## Decisions (workshop, 2026-10-17)

| Question | Decision |
|---|---|
| How the recording reaches FL | **Both**: a MIDI file (drag it from the plugin window into FL, or Save MIDI...) first; **live MIDI out** into FL's recorder as the second step. |
| Tracks | **One track per instrument.** "If the song used 5 different instruments, I expect 5 different tracks, all mapped to an instance of the BrokenNes VST, so that it replays it as is." Rare cases where an instrument changes in the middle of a note/song are **not** supported (ignore, count, say so). |
| Timing | **Detect the game's tempo** and write it, so bars line up (a heuristic: report its confidence; fall back to exact time at FL's tempo when it cannot find one, and say so). |
| Extras | **Pitch bends and slides** (the driver's vibrato, slides, sweeps), **volume changes** (velocity + a volume/expression controller), **a preset per instrument** (ripped, named like its track, ready on the Presets chip in direct mode), **root-note detection** (each sample's real musical pitch, so the piano roll shows the right notes; the preset's tuning compensates so the replay pitch is unchanged). |

## What exists (do not rebuild it)

- `SessionGame` feeds `SpcWriteLog` (Plugin `SpcRecipe.cs`): every SPC700 write to the S-DSP with the DSP's 32 kHz sample clock, allocation-free on the audio thread; a ring of 262,144 writes (`Capacity`), last 30 s used for game voices.
- `SpcRecipes.Notes(...)`: every note of a window with its voice, start, end (32 kHz samples), key-off flag and its own macro (`SpcRecipe`: SRCN, ADSR1/ADSR2/GAIN, VOL L/R, pitch at key-on, noise/echo/pitch-modulation flags, timed pitch (cents)/volume/envelope/flag changes). This is most of a transcription already.
- Presets (`*.bn2preset`, library, `PRS1` project copy, Presets chip and per-console shortcuts, `SnesSampler` engine in direct mode, the SNES note block = game voices) and the instrument model (`Instruments/`).
- The plugin's Direct mode follows FL's per-note pitch automation and slides (`bend`, `slide` checks); the Presets chip plays a preset from FL's notes.

## Architecture (the lead's plan; refine with evidence)

1. **Recording session** (SNES first): Record arms a session on the emulator (Runaway frozen or not); recording starts when the game runs (Runaway off) or when FL's transport starts (an option); Stop ends it. The session keeps EVERY S-DSP write from start to stop: a capture that does not drop (preallocated chunks handed over from the UI thread, nothing allocated on the audio thread), capped by memory with an on-screen note when the cap is reached. The register state at the start is kept (as `SpcWriteLog.BaseRegs` does).
2. **Transcription**: notes from the session (reuse/extend `SpcRecipes.Notes` over the whole session). **Instrument = sample (SRCN)**; a note whose SRCN changes while it sounds keeps its key-on SRCN (counted). Per instrument: the most common key-on envelope/flags become the preset's settings; the per-note pitch macro becomes **pitch bend** (choose and write a pitch-bend range with RPN 0, wide enough for the sweeps found, and check the plugin honours it); volume becomes **velocity** at the key-on plus a **volume/expression controller** for the changes (state which). **Root note per sample**: estimate the sample's fundamental (BRR decoded; the loop is the best place) and express notes in musical pitch; the preset gets a tuning offset so that a MIDI note + bend reproduces the game's pitch register **exactly** (prove: transcribe, replay through the preset engine, compare the S-DSP pitch registers written). **Tempo**: estimate BPM and phase from the onsets (inter-onset histogram / autocorrelation; many SNES drivers tick at a fixed timer), write a tempo map, place notes in ticks; report confidence and fall back to real time at FL's tempo when uncertain. Thinning/caps for absurdly dense corrupted states (state the numbers on screen).
3. **Mapping to BrokenNes2 instances** ("5 instruments, 5 tracks, each mapped to a BrokenNes2 instance that replays it as is"): each recorded instrument becomes a preset (round 6 format, the recording's name + the instrument) and a MIDI track with the same name. Design the easiest way for the user to get N BrokenNes2 channels each playing its track: e.g. the Presets chip offers "from the last recording: track N" (or picks the track whose name matches), and per-track drag handles in the plugin window (drag "Track 3: sample #7" onto the channel). FL's own MIDI import creates channels per track; check what it creates and how the user turns them into BrokenNes2 instances, and document the shortest path. Note: the plugin SDK cannot create FL channels itself (verify).
4. **Getting it into FL**: (a) the MIDI file: SMF type 1, one track per instrument, tempo map, written to a temp folder and offered by **drag and drop** from the plugin window (OLE `DoDragDrop` with a file) and a **Save MIDI...** button; (b) **live MIDI out** (step 2): the plugin sends the notes as MIDI while the game plays (the Fruity SDK's MIDI out for generators) on one channel per instrument, so FL can record it into piano rolls; document the routing; this is the riskier half and is not tested by any script without FL.
5. **The project** keeps the session (its writes or its transcription, versioned section, CRC) so the user can re-export after reopening.
6. **Replay without the game**: the N tracks on N BrokenNes2 instances on the Presets chip. Known limits to state on screen and in the docs: effects BETWEEN voices (pitch modulation, the shared echo buffer, the noise clock shared by all voices) cannot be replayed by separate instances (each has its own S-DSP); a later step could add a multi-timbral SNES instance that plays several tracks on one S-DSP. The game's song data/sequencing is now captured as notes (that is the point), but random or state-dependent behaviour is captured as it happened in that one take.

## Verification (every verifier shown able to fail; no sound card: measure)
- Capture: no write lost over a long take (count), nothing allocated on the audio thread.
- Transcription round trip: replay the MIDI through the preset engines and compare the S-DSP pitch/volume/envelope registers written per note with the game's own writes (exact pitch where the design says exact; state the tolerance elsewhere); on Super Mario World and Donkey Kong Country (`X:\EMULATION\Super Nintendo\Super Nintendo (U)\`) and on a heavily corrupted state.
- Tempo: on songs whose driver tempo is known (or measured from the driver's timer), the estimate is within a stated error; a corrupted song reports low confidence instead of a wrong tempo.
- Root notes: the estimate on samples of known pitch (a generated test sample; a few real instruments checked by FFT); exact replay pitch whatever the estimate.
- MIDI file: valid SMF read back by an independent parser (and by FL's import when the user tries it: not testable here).
- The plugin flow with real mouse messages (Record, Stop, Save, drag source), the project section, damaged/newer sections refused.
- All existing suites stay green.
