# BrokenNes Lite UAT, 2026-11-14

- **Base:** main `cc2e16f1`, worktree `uat-lite-1114`.
- **Harness:** `UAT/lite/uat1114/` (README inside). It drives a headless Edge over the DevTools protocol with
  background throttling turned off. Touches are real `Input.dispatchTouchEvent` events and keys are real
  `Input.dispatchKeyEvent` events. The file picker is driven through `DOM.setFileInputFiles` and drag and drop
  through `Input.dispatchDragEvent`. Every run gets a fresh profile, and only the PIDs it started are killed.
- **Builds:**
  - **AOT:** `dotnet publish -c Release -p:EnableWasmAot=true` (dotnet.native.wasm is 27.5 MB).
  - **Debug:** `dotnet publish -c Debug`.
  - Both were published from the worktree into scratch. `WebLite\bin\Release-Publish` was not touched.
- **ROMs:**
  - Our own games from T:\VRUN_Demo.
  - The GB test ROMs from `Windows\Resources\gb-test-roms`.
  - A few commercial ROMs from X:\EMULATION per console, kept in scratch only. None of them, and none of their
    screenshots, are in git.
  - All screenshots are in scratch, under `scratchpad\out\`.
- **Machine load:** shared with other agents. CPU load was 44-100% during the runs and is recorded next to every
  speed number. Speed was measured twice: in the middle of the run and again at the end.

## Bugs (with repro), ordered by severity

1. **High: Master System APU "NES-FM:FIX" crashes the game.**
   - Repro: load `VRUN_CTW_SMS_2026-11-10_mmc3.sms` (any SMS game), open APU core menu, pick "FIX with the FM chip".
   - Result: the console logs `Console session frame failed System.IndexOutOfRangeException at NesEmulator.Sega.SmsSession.RunFrame()`.
     The frames stop (fps 0) and the picture freezes. Reproduced twice.
   - Screenshot: `out\aot_core_sms_APU_NES-FM_FIX.png`.
   - NES:FIX (without FM) works. The code is in `mix\SmsFmSoundOnNes.cs` and `sega\SegaSoundFactories.cs`.
2. **High: no touch controls in landscape, on every console.**
   - Repro: phone at 844x390 landscape with touch, load any ROM, tap the fullscreen button.
   - Result: `toggleFullscreen` only builds the mobile view in portrait (`nesInterop.js` `isMobilePortrait`).
     Landscape asks for real fullscreen of `#screen-shell` only, so there is no `#touch-controller`.
   - The picture is also taller than the screen (canvas 479-641 px in a 390 px viewport), so it is cut off.
   - Screenshot: `out\touch_nes_landscape_layout.png`.
3. **Medium: NES on the FIX cores misses 60 fps under load in AOT** (badge 54-56; FrameTick 15-17 ms). Every
   other console has 2.5x-4x headroom on the same machine. Worth profiling the NES path in Lite.
4. **Medium: x86/DOS isn't offered in Lite.**
   - `Consoles.X86Enabled` is never set in `WebLite/Program.cs`; only WideMess is turned on. Re-confirmed.
   - There is also no x86 touch layout or on-screen keyboard: no `data-layout=x86` CSS. Re-confirmed.
   - Decide whether this is intended.
5. **Medium: the touch pad ignores mouse and pointer events.** A held mouse press on A leaves `nesInputState[0]`
   false on every console. Touch-screen laptops that send pointer events, and pens, can't use the pad. Re-confirmed.
6. **Low: NES WF APU logs "[NES] SoundFont library load failed" and plays nothing.** The SoundFont asset is
   probably missing from the Lite build.
7. **Low: NES Load state gives no status.** SNES, WMS, GB, GBC, SMS, GG and MD say "State loaded". NES Save does
   say "State saved (compressed)".
   - This replaces the first pass's "no save/load feedback" finding, which was wrong: the selectors are
     `.btn-save-state` / `.btn-load-state`.
8. **Low: changing the sound core blocks loading after a reload.**
   - The sound-core choice persists, so after a reload a state saved with the old core is refused.
   - The message is clear ("Switch the sound unit to SFC ... a state is never loaded into a different sound
     unit"). This is by design (no silent fallbacks), but a one-tap "switch back and load" would help.
9. **Low: some corner touches on pad buttons miss, and the system row is small.**
   - Corner touches are taken 15% in from a button's bounding-box corner. In AOT, 1 miss on NES (A) and 3 each
     on GB/GBC (round buttons, tilted Select/Start); no misses on the other consoles.
   - The Debug build missed many more, which looks like a timing effect.
   - Centre touches are 100% on all consoles.
   - System-row buttons are 31 px tall and Select/Start 61-67x31 px, under the 40-44 px touch guideline.
10. **Low: the Game Boy "Look" row overlaps on a phone.**
    - At 390 px wide, the INV. BG / INV. SPRITES checkboxes sit on top of the "Look" label and the select text.
    - Screenshot: `out\touch_gb_portrait_layout.png`.
11. **Low: stale touch layout after a console change.** After loading a SNES ROM in a tab that was showing a
    WideMess game, `#touch-controller` keeps `data-layout="wms"` (same pad, so it is harmless today).
12. **Low: CGB-compatible ROMs run as DMG.**
    - `VRUN_Vaults_of_Obsolete_Code_V6_68475f9.gbc` (header $143 = $80) and Dr. Mario DX boot on the Game Boy
      console with the green palette.
    - cgb-acid2 ($C0) and Link's Awakening DX ($80) boot as Color.
    - Check how the console is chosen for $80 ROMs.
13. **Low: noisy logs on every hot switch.** `[EngineState] ... engine section of another build or core ... re-keyed`
    is logged at console.error level on every foreign-chip switch (hundreds in the sweep).
14. **Low (build hygiene): `WebLite\bin\Release-Publish` is stale** (2026-09-27). The `brokennes-lite-maxspeed`
    launch entry serves it. Also, a plain `-c Release` publish is not AOT: it needs `-p:EnableWasmAot=true`.
    Re-confirmed.
15. **Info: Butchering mode isn't exposed in Lite.** Lite has the RTC, Glitch Harvester and Imagine.
16. **Info: a `?rom=` ROM doesn't appear in the ROM list.** Uploaded and dropped ROMs do, and they persist across
    a reload.

## Fix order

1. SMS `NES-FM:FIX` crash (bug 1).
2. A landscape mobile layout with the touch pad, and the picture fitted to the screen height (bug 2).
3. NES FIX speed in Lite (bug 3).
4. Decide on x86 in Lite. If yes, add an x86 layout with a keyboard (bug 4).
5. Pointer/mouse support on the pad (bug 5). While there, enlarge the system row and soften the corner dead
   zones (bug 9).
6. The small ones: WF SoundFont (6), NES Load status (7), GB Look row overlap (10), stale touch layout (11),
   CGB-compatible ROMs as Color (12), log level (13), republish Release-Publish with AOT (14).

## How to rerun

See `UAT/lite/uat1114/README.md`. The phases are `boot`, `speed`, `cores`, `touch`, `state`, `battery`, `misc`;
the full suite takes about 2.5 h on a loaded machine (the core sweep is ~95 min of that).

Not covered:
- Audio starting without a user gesture: the harness runs with autoplay allowed.
- Real hardware phones.
- SRAM games that write within seconds.
- Desktop fullscreen in a headed window.

### Still open

1. **NES on FIX still has no headroom** (16.5 ms against 16.7 ms at 94-100% machine load; badge 55-58). The cores
   lane's PPU_FIX trims gave only ~3-8%. The real fix is a different PPU stepping scheme (per-scanline fast path or
   batched PPU catch-up) with timing proof. Re-measure on a quiet machine first: this run had the CPU pinned.
2. **Genesis** is also at the edge under this load (16.3 ms; it was 11.6-12.9 ms on a calmer machine).
3. **x86 in Lite runs at ~20 fps** (48 ms per frame). Needs its own speed pass.
4. A bare DOS .EXE needs the 33 MB FreeDOS disk, which Lite does not ship (user decision: download size).
5. WF SoundFont: loaded from unpkg at runtime; offline samples need the files bundled (download approval).
6. Stale `data-layout` after WMS -> SNES (bug 11): left as is; a SNES game runs on the WideMess by design when the
   WideMess is selected. User decision.
7. Desktop `MainForm.Consoles.cs` still follows the selected console for dual-mode GB carts (Lite now picks Color).
8. Battery fuzz: two undo-mismatch findings (NES seed 319110 picture-only on FIX/FIX/FIX, GBC seed 319080 STATE byte
   124 on GB-NESCLOCK). Both reproduce identically on main `e59c41a4` without the Lite work, so they are older.
