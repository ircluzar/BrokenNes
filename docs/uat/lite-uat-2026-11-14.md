# BrokenNes Lite UAT, 2026-11-14 (partial: blocked by the test environment)

Base: main cc2e16f1. Builds: Debug (`brokennes-lite`, port 5013) and a fresh AOT Release publish made in a
scratch worktree (served statically). ROMs came from T:\VRUN_Demo and the GB test ROMs and were loaded with
`?rom=http://127.0.0.1:5099/<file>` (a local CORS server in scratch). No commercial ROMs were used.

## Why this run is partial

1. **The browser pane was hidden for the whole session.** The session isn't open in a window, so `show_pane`
   could not raise it. A hidden page is throttled by the browser: both Debug and AOT ran at **about 1 fps**.
   That means fps, sound, input timing and boot-to-gameplay could not be judged. The AOT build should not
   be blamed for this number.
2. **Touch input can't be exercised.** The browser tool sends mouse clicks even with the mobile preset.
   The touch pad listens only for `touchstart/touchmove/touchend` (nesInterop.js `initTouchController`), so a
   click never reaches it. The layouts were checked by eye, and the input path was checked by reading the code.
3. **Simulating a file drop was refused.** The drag-and-drop and file-picker paths were not exercised. The
   `?rom=` URL path was used instead.
4. **The benchmark is behind `DebugUnlocked`**, so there was no throttling-proof speed number either.

**To finish this UAT:** run it with the Claude window and the Browser pane visible, or on a real phone over
the LAN.

## Findings

| # | Severity | Finding | How to reproduce |
|---|---|---|---|
| 1 | High (test infra) | The UAT can't measure anything time-based while the Browser pane is hidden. Every console shows ~1 fps. | Hide the pane, open any ROM, read the FPS badge |
| 2 | Medium | **x86/DOS isn't in Lite's Console list.** `Consoles.X86Enabled` is never set in WebLite/Program.cs; only `WideMessEnabled = true` is. Check whether this is intended. | Open Lite, open the Console dropdown: NES, SNES, GB, GBC, SMS, GG, MD, WMS |
| 3 | Medium | **There is no touch layout for x86.** The `#touch-controller` CSS has no `data-layout=x86` rules and there is no on-screen keyboard. If x86 is enabled in Lite, a phone gets a NES pad that can't type into DOS. | Code: Nes.razor 241-283, Nes.razor.css 302-340 |
| 4 | Medium | **The touch pad ignores pointer and mouse events.** Desktop touch-screen hybrids that send pointer events, and automated tests, can't press pad buttons. Also, a `touchstart` on a system button returns early and drops any other touches in that event. | nesInterop.js:2053 |
| 5 | Low | Save state and Load state give no visible feedback: STATUS stays "Emulation running...". | Click Save state, then Load state |
| 6 | Low | `WebLite/bin/Release-Publish` (the folder the `brokennes-lite-maxspeed` launch entry serves) is stale, dated 2026-09-27. maxspeed tests run against old code unless it is republished. | `ls -l WebLite/bin/Release-Publish/wwwroot/_framework` |
| 7 | Low | Benchmarks are only reachable with Debug unlocked, so a user can't measure their device. | Performance panel |
| 8 | Info | Butchering mode isn't exposed in Lite's UI. Lite has the RTC, Glitch Harvester and Imagine. | Page sections |
| 9 | Info | A ROM loaded through `?rom=` doesn't appear in the ROM Manager list or its recent list. | Load with ?rom=, look at the ROM table |
