# BrokenNes: Sega cores, hand-off build {{TAG}}

Built {{DATE}} from commit `{{COMMIT}}`. This build carries the three Sega consoles (Master System, Game Gear, Genesis) at the finish the Game Boy and SNES got: playable rosters checked against the reference emulators, saves and save states, every core swappable while a game runs, picture and sound bridges to the NES, SNES and Game Boy cores, and the FL Studio plugin with the Sega chips, ROM mode, stems and Instrument Runaway. `CERTIFIED.txt` lists what the scripts did and did not cover for this exact build.

**What only you can do:** nobody has heard any of the sound (the build machine has no sound card) and FL Studio itself has not run the plugin. Section 5 is a 15-minute listening checklist; that is the last open item of the whole exercise.

## 1. Put the plugin into FL Studio (the way you will normally do it)

1. Close FL Studio.
2. Start the app (`Run BrokenNes.cmd`), then **Config > Synthesizer Mode > Install to FL Studio...** (or run `Install to FL Studio.cmd`, the same thing). Pick your FL Studio version(s), accept the administrator prompt.
3. Start FL Studio, rescan plugins if it does not appear on its own, and add **BrokenNes2** as an instrument (the name has no other label now). Delete nothing: the installer replaces the old plugin file, and your remembered plugin settings move across.
4. To go back to the previous plugin, run the installer from the previous build you were using.

In the plugin: a **Master System PSG** chip, a **Master System FM (YM2413 + PSG)** chip (the Instrument control picks one of 22 instruments: the chip's 15, six designed here, the PSG square), a **Genesis (YM2612 + PSG)** chip (Instrument = one of 16 FM patches), and **ROM mode for Master System, Game Gear and Genesis games**. In ROM mode every sound unit hands out its voices as **stems** (PSG tone 1-3 and noise; Genesis FM 1-6 and the DAC; Master System FM 1-9 and the five rhythm voices) that add up to the game's mix. **Instrument Runaway** works for the Sega chips: freeze a game, and the PSG, YM2413 and YM2612 (plus the sounds found in the Genesis DAC's write stream) play polyphonically from FL notes, saved with the project. The standalone synth (`Run standalone synth.cmd`) is a quick sound check without FL.

**Games:** use your library under `X:\EMULATION` (Sega Master System, Sega Game Gear, Sega Genesis). The Master System files are `.7z` archives: **unzip them first** (the app takes `.zip`, not `.7z`). `docs\projects\sega-rosters.md` (in the repo) lists the 60 games the work was measured on, easiest first.

**D-pad protection (new):** pressing opposite directions together (Left+Right, Up+Down) sends neither, as on a real pad; it is on by default in the desktop app, the Lite page and the plugin, and each has a tick box ("allow opposite directions") to turn it off. Recorded input and movies are not touched.

**Keys (default):** arrows; **X** = A / button 1, **Z** = B / button 2, **Enter** = Start, **Space** = Select (Master System: Pause; Genesis: Mode). Genesis six-button pad: **A** = X, **S** = Y, **W** = C, **Q** = Z. A game pad works too; remap in the controller window as usual.

**Saves** live in `%APPDATA%\BrokenNes\SmsSaves`, `GgSaves`, `MdSaves` (one file per game, named by hash). **Save states:** **F7** = quick save, **F5** = quick load, and Save State... / Load State... in the menu, for Master System, Game Gear, Genesis, Game Boy **and SNES** games (the SNES since round 5: about 100 to 150 KB a state, taken in about 16 ms, for every game of the roster including the DSP-1, SA-1 and Super FX ones); the quick slot is one file per game in `%APPDATA%\BrokenNes\States`. In the Lite page the **Save state / Load state** buttons do the same for every console, the state kept in the browser (IndexedDB). A state belongs to the sound unit it was saved with (and, on the SNES, to the cartridge chip: the homemade DSP-1 and Nintendo's DSP-1 firmware are different chips): loading it after switching the APU core is refused with a message that names both units, and the game keeps running as it was. A SNES state saved with a NES chip as the sound unit keeps the game exactly; the NES chip's own phases start again.

## 3. Swap anything while the game runs (the Console menus)

The **CPU**, **PPU** and **APU** menus of a Master System, Game Gear or Genesis game list the console's own chip and every other family's chip as `NES:<chip>`. Pick one while the game runs: the game keeps going. If a swap cannot be done in place the app restarts the game and says why in the title bar. Some combinations are dead on purpose and are marked so in the menu with the reason (for example a Z80 or 68000 running a NES game).

**The Sega machine menu** (new, in the app's menus): video standard (NTSC or PAL), the Genesis board model 1, 2 or 3, the Master System board. Saved in the config and applied when the next game loads.

## 4. Sound and picture options (this is the part to listen to)

- **Master System** APU menu: `SMS` (the PSG), **`SMS-FM`** (adds the YM2413: only Japanese games use it; reload the ROM after switching), `NES:<chip>` (the Sega sound replayed on a NES sound chip) and **`NES-FM:<chip>`** (the YM2413 and PSG together on a NES chip, with a voice-stealing policy when there are more voices than channels: a loud newcomer takes the quietest pulse, the rest are dropped and counted).
- **Genesis** APU menu: the stock unit (real Z80 + YM2612 + PSG) and `NES:<chip>` (FM timbre is lost, the DAC becomes noise hits). The sound chips of the SNES and Game Boy families are now converted to the console's sample rate (they used to play at the wrong speed).
- **NES** APU menu: **`SMS`** ("From the Master System": a NES game on the PSG) and **`MD`** ("From the Genesis": a NES game on real YM2612 FM voices; the patch is chosen in the volume panel, 16 timbres). Notes below the PSG's lowest note (about 109 Hz) are played octaves up (counted, not hidden).
- **Picture:** the PPU menu lists **`NES:<chip>`** (the picture drawn by a NES picture chip, e.g. `NES:FIXS`; `NES:DMG` shows the 160 x 144 Game Boy window; the 4-shade chips lose colour on purpose). The NES PPU menu has **`SMS`** and **`MD`** (a NES game drawn by that VDP). Cost: the Genesis drawn by a NES picture chip runs at about 2x real time on the desktop but **below real time in the browser build**.

## 5. Listening and playing checklist (15 minutes, this closes the exercise)

Please note what is wrong, not what is right; a short description of a sound is enough.

1. **Master System, 3 minutes:** Alex Kidd or Sonic 1 for the PSG (tone, noise, volume steps); then a Japanese FM game with `SMS-FM` (Phantasy Star Japan, Fantasy Zone II): does the FM music sound like an FM chip, and are the drums right?
2. **Game Gear, 2 minutes:** Sonic Chaos or Shinobi: left/right panning of the PSG (the stereo port).
3. **Genesis, 5 minutes:** Sonic 1 (green hill music, ring and jump effects), Streets of Rage 2 (drums and bass), Ecco. Is the **FM to PSG balance** right (PSG is a choice, quieter)? Is it too bright or harsh (no analog low-pass is modelled)? Do speech and drum samples (the DAC) sound right? Press F7 mid-song and F5 later: does the music resume cleanly?
3a. **SNES save states, 2 minutes (new):** Super Mario World or any SNES game: F7 in a level, play on, F5: you are back exactly where you pressed F7 (music resumes, not restarted). Try a Super FX game (Star Fox, Yoshi's Island) and a DSP-1 game (Super Mario Kart), and the same in the Lite page with its Save / Load state buttons. Switch the APU core to the silent `HLE` unit and press F5: it must refuse and say the state was saved with the SFC sound unit.
3b. **Swap while playing:** during a Genesis song switch APU `MD` to `NES:FIXS` and back: a brief change of voices is fine, a hang or a squeal is not.
4. **FL Studio, 5 minutes:** play notes on the Master System PSG, Master System FM and Genesis chips (try several patches); load a Genesis ROM in ROM mode and solo two stems; freeze a game with Instrument Runaway and play it from the keyboard; save the project, reopen it.
4a. **Corruptions in the plugin (new), 10 minutes:** in the desktop app load a SNES game (Super Mario World), open the Glitch Harvester, corrupt it a few times until something sounds interesting, keep the ones you like in the stockpile and press **Save file...** (a `*.stockpile.json`, no ROM inside). In FL put BrokenNes2 in ROM mode with the same game, press **Corruption** (bottom left, next to Inputs), **Open stockpile...**, pick your file: entries that fit the loaded game have a green dot, the others say why not in orange. Pick one, tick "Switch Instrument Runaway on by itself after the corrupted game has played for" and leave the time at **10 s** (the button next to it steps 0 / 5 / 10 / 20 / 30 s), press **Start**. The corrupted game plays: **listen to it**, the screech or the wrong notes are what the next step takes. After the time Instrument Runaway switches itself on. Its picker lists the corrupted samples or patches and, below them, **game voices**: how the corrupted sound program played each instrument (a pitch that wobbles or runs away, a volume that swells, an envelope gone wrong, a noise that stays on). Pick a game voice and play it from the keyboard: **C5 plays the game's own pitch**, the other keys move it, and the sound should be the instrument as the corrupted game played it, not the clean one. (With the time at 0 s it freezes at once, which is how it used to work: only the corrupted memory is taken and the game voices are missing: the result line says so.) If the banner says it heard no notes, the game had stopped playing: try another corruption, or press Instrument Runaway yourself while the screech is playing (the last 30 seconds are used). A game voice is **one note the driver played**, replayed when you play a key: the game's song and the order of its notes do not come with it (see "Game voices" in `Plugin/README.md` for what it cannot reproduce). Save the project, reopen it: the corrupted game and its instruments come back, and switching Runaway off carries on from where the game was. **Remove corruption** puts the game back where the corruption was made. The same works for Game Boy, Master System, Game Gear and Genesis games; the NES is not wired into the plugin's Corruption window yet.
4b. **Push into the game (new), 10 minutes:** in FL put BrokenNes2 in ROM mode with Super Mario World (SNES), let the music play, press **Instrument Runaway** and open the **Instruments** tab. Pick the sample the music is using (the list marks the ones the game was playing), set its **Tuning to +1200** (an octave up) and press **Push into the game**. The line under the buttons says exactly what it did. Now switch Instrument Runaway **off**: the game's own music carries on with that instrument an octave higher (the same notes, higher). Freeze again, press **Remove from game**, switch Runaway off: the music is the game's own again. Try **Randomise** on a sample and push that: the instrument sounds different in the game's own music. **Save the project and reopen it:** the pushed instrument is still in the game (and the list says "in the game"). What to expect per console: **SNES** the sample's bytes stay until the game loads other sounds over them; envelope, volume, tuning and echo/noise flags are forced on every note of that sample. **Genesis** (Sonic 1): an FM patch edit is loaded at every note of every channel playing that patch; a DAC drum can be replaced. **Game Boy**: the wave channel only. **Master System FM**: the user instrument only. Pulse and noise channels, the PSG and the NES are refused with a reason on the status line (that is correct, not a bug). A game that reloads its sound set (a new level on some games) puts the original sample back; the forced settings stay until you press Remove.
4c. **Presets: rip, corrupt, keep, play with no ROM (new), 10 minutes:** in FL put BrokenNes2 in ROM mode with Super Mario World (SNES), let the music play, press **Instrument Runaway** and open the **Instruments** tab. Pick a sample, press **Randomise** a couple of times (or use the steppers), then **Send to Presets**: a name field opens on the line under the buttons, offered with the instrument's name; type a name and press **Enter** (**Esc** cancels). The line says it was added. Now add a **second** BrokenNes2 in FL, open its **Sound chip** list and pick **PRE-SNES** (or **PRESETS**): the picture area becomes a banner and the Instrument row becomes a **Preset** picker; pick your preset (or open the **Presets** tab, select it, press **Load**) and play notes: it is the corrupted instrument, with **no ROM loaded** (the first instance can even be deleted; the preset is saved in the project). Try **Audition** in the Presets tab, **Rename**, **Export** and **Import**, and **Delete** (two clicks; the instance keeps playing and the tab lists it as kept in this project). Save the project, reopen it: the preset still plays. Do the same with a Game Boy game (a wave instrument), a Master System or Genesis game (a PSG tone, an FM patch, a drum sample) and a NES game: a NES pulse, triangle or noise preset plays; a NES DMC preset says it cannot be played yet. Files are in `%APPDATA%\BrokenNes\Presets` (one folder per game); nothing in there ever holds a ROM. If the game was listened to by Instrument Runaway (a SNES game that played for a while before you froze it), a preset can also carry **the way the game played the sample**: on the preset's instance the *Channel* row becomes **Voice**: pick *Game voice 1* and listen to the difference from *Plain sample, as sent*. Note what sounds different from the same instrument in Instrument Runaway (it should sound the same: that is what the build was measured to do).
4d. **Test MIDI export: does your FL song replay right in VRUN's sound engine? (new), 10 minutes:** this is the step that certifies a composition for the VRUN game, and only your ears can do it.
   1. **Compose** (or open) a song in FL Studio for the NES: up to four parts, for example a lead, a second voice, a bass and drums on MIDI channel 10. Play it in FL until it sounds good.
   2. **Export MIDI from FL:** File > Export > MIDI file..., save it somewhere you will find again (for example next to the FL project, `mysong.mid`).
   3. In FL, add **BrokenNes2** (any instance; it does not need to be in ROM mode), press **Test MIDI export** (top of the plugin window, next to its name), then **Open MIDI...** and pick `mysong.mid`. The window shows the song's name and a few lines: which MIDI channel each NES channel plays, notes that were dropped (more than four channels), notes thinned (more than one change per frame on a channel), the loop length, whether a channel was **truncated** (too long for the game's 1,280 bytes), ignored tempo changes and pitch bends. These lines are why the replay can sound different from FL. The song plays at once; the picture shows VRUN's sound-test player with your song's name and its position.
   4. **Listen**, and compare with FL: press FL's Play: the song restarts with FL (**Follow FL's transport** is ticked); FL's Stop stops it. The four NES channels can be put on four more BrokenNes2 instances (Channel: Pulse 1, Pulse 2, Triangle, Noise) to solo them in FL's mixer.
   5. **Edit in FL, export again over the same file, press Reload:** the new version plays from its start (Reload says so; if it says the file has not changed, FL saved it elsewhere).
   6. Save the FL project and reopen it: the song comes back (the project keeps the MIDI file itself).
   Tell me: does it replay like FL (notes, timing, the loop)? Which differences are not explained by the lines in the window? Try a file that is not a MIDI and a song with only drums: each is refused with a reason, and the song that was playing goes on.
4e. **Record a SNES game's music into FL (new), 15 minutes:** this is the step that turns a (corrupted) game's song into FL notes; only FL itself can show whether its import and routing do what the plugin prepares.
   1. In FL put BrokenNes2 in ROM mode with **Super Mario World** (SNES). Press **Record** (top of the plugin window, right of Test MIDI export): the Record window opens. Press **Record** in it while the overworld music plays, let it play 20 to 40 seconds, press **Stop**. A moment later the window shows the tracks (one per instrument, "SMW ... - 01 sample 2" and so on) and what it found: the notes, the tempo (Super Mario World's overworld: about 141.6 BPM; set FL's tempo to the number it gives), and the things that keep the replay from being the game.
   2. **The host log now runs by itself** while the tracks are on offer (the Record window's box reads "Log FL's calls (on now)"): `Documents\BrokenNes2 host log.txt` gets what FL does to every BrokenNes2 (created, its state, the values FL sets, the channel's name FL gives, joined or not, its first notes). Nothing to tick. If anything below does not work, send me that file. Optional, for the name shortcut in step 4: untick FL's **Options > General settings > Auto name channels** before you replace (FL then keeps each imported channel's track name instead of renaming it "BrokenNes2").
   3. **Drag the big handle** ("Drag ... .mid into FL") onto FL's **channel rack**. FL's MIDI import window opens: keep one channel per track and import. FL makes one channel per track (MIDI Out channels), with each track's notes in its piano roll.
   4. **Replace each imported MIDI Out channel by BrokenNes2** (right-click the channel > Replace > BrokenNes2), in any order, and keep the game's BrokenNes2 open on its **Record** window. **After each replace the CHANNELS line counts one more**: "1 channel joined, 0 found their track", then "2 channels joined, 0 found their track", ..., and lists each one ("#4: waiting for its first note"). The new channel's own editor shows a green banner **LINKED TO THE RECORDING: press Play in FL and I will find my track from my first note**. If FL tells the plugin the channel's name and it is the track's name, that channel takes its track at once: the count says "... 1 found its track" before you press Play (if FL renamed the channel "BrokenNes2", the list says so: see step 2).
      **If the count does not move after a replace:** open that channel: a red banner **TRACKS OF "..." ON OFFER** says why it did not join (for example "its project state holds a preset") and has a big **Link to recording** button: press it. Or press **Link all BrokenNes2 channels** in the Record window (it links every BrokenNes2 that is not linked, the ones you made before recording too). Then tell me what the banner said and send the log.
   5. Press **Play**. Each linked BrokenNes2 recognises its track from the first note FL gives it (the key and where the note is in the song) and plays that track's preset from that note on; a moment later it moves itself to the tracks' emulator on the **PRE-SNES** chip. The count rises with each one: with 6 channels you should end on **"6 channels joined, 6 found their track"**. The line above CHANNELS in a channel's Record window says "This channel plays track N ... (recognised from its notes)" (or "found by its channel's name"), and each row shows how many channels play it. If one did not find its track, press **Play here** on the right row (that always works), and tell me which one it was (the log says why).
   6. Listen: the song should sound like the game (the corrupted one if you recorded a corruption). With **Bends + volume from the recording** ticked (the default) each channel takes the recording's own pitch bends and volume, because FL's import loses the volume changes and squeezes the bends; untick it to hear what FL itself kept (then the bends follow FL's channel pitch at FL's pitch bend range, and the volume only the velocity). Tell me: are the notes in the right places on the piano roll (bars lined up)? Do slides and vibrato sound like the game, ticked and unticked? Which track sounds wrong?
   7. Try **Lanes** (tick it before or after recording: the tracks are made again): instruments that played two notes at once get extra tracks and the "shared" counts go away.
   8. **Live MIDI out:** tick **Live MIDI out** in the Record window (port 1; - and + change it). In FL set a channel's MIDI input port to the same number (and its pitch bend range to 12) and arm FL's recording: the game's notes arrive as it plays, one MIDI channel per instrument. Tell me whether FL received them at all (this is the part nothing here could test).
   9. Save the FL project and reopen it: the Record window shows the same recording again (the presets are not added to the library twice), and every replaced channel still plays its track.
   Also try **Donkey Kong Country** (23 instruments: past 15 the MIDI channel numbers repeat on separate tracks) and a **corrupted** game from the Corruption window (a song with no steady tempo says so and keeps the notes at their real times).
4f. **Record a NES game's music into FL (new), 15 minutes:** the same window and the same steps as 4e, on the NES.
   1. In FL put BrokenNes2 in ROM mode on the NES with **VRUN** (the built-in game; or any NES game file, or a Test MIDI export song). ## 6. Known limits (so you do not report these as new)

- **Genesis:** two roster games are still "working", not "playable": **Strider** (its intro matches BlastEm exactly but its gameplay drifts: the level load finishes a frame later than on BlastEm, a VDP-port timing question) and **Shinobi III** (the game's random number is one idle-loop iteration off after about 700 frames: a game-side phase, not an emulation rule). Comix Zone differs from BlastEm by 1 to 3 pixels in every picture, Streets of Rage 3 is one frame behind at the last picture. Fatal Rewind and Killing Game Show run now. Not implemented: 3-wire EEPROM games, the SVP (Virtua Racing), some pirate mappers. One Titan Overdrive 1 frame (1007) is chaotic and differs from BlastEm; the H40 CRAM-flicker phase differs slightly (about 0.3 percent in the 68000's VDP write cost).
- **Master System / Game Gear:** a handful of games differ from Mesen in isolated frames (Fantastic Dizzy, Bubble Bobble, Black Belt and others); Mesen's own Z80 instruction lengths differ from the Zilog manual in a few instructions and this emulator follows the manual (14 games match Mesen only with Mesen's lengths: that is a tool setting, not a bug). Game Gear Castle of Illusion hangs at a blue screen (it does in Mesen too). Mesen drops some fast VDP writes during the picture; this emulator keeps every byte.
- **Sound:** the FM chips and PSG were compared with oracles sample by sample and by register logs, but the YM2413's snare/cymbal/hi-hat noise sequence is not the oracle's; YM2612 envelopes/SSG-EG/CSM are within stated bounds, not exact. The 6 designed YM2413 instruments and every patch are untested by ear.
- **Corruptions:** farming console games (SNES, Game Boy, Master System, Game Gear, Genesis) is in the desktop app only, the Lite page cannot; starting a NES corruption in the plugin is not done yet. A corruption replays from power-on when its console game cannot hand over a saved machine: the longest replay is 10 minutes of game time (36,000 frames) and longer ones are refused with the number. How good a corruption sounds as an instrument is the one thing nobody has heard. **Game voices** (SNES and Genesis only; the Master System, Game Gear and Game Boy still take the copy of their registers) replay one note of the corrupted sound program, with FL's pitch on top: not the song, not the order or timing of the game's notes, not behaviour that is random or different every note, not the SNES's pitch modulation or echo feedback history. The one kind of state the lab found that they do **not** reproduce is a loud, harsh screech whose character comes from effects between voices (pitch modulation, noise, a strong echo feedback): 2 of 140 random SNES corruptions, and in both the game voices came out no closer to the game than the plain instrument or than silence (`docs/projects/round6-runaway.md`, "Screech hunt"); if the screech you farmed is not in the game voices, say which feature is missing (a steady noise, a high wobble, a ringing tail). They were measured against the game's own sound by scripts, not listened to: nobody has heard them on a real corrupted game yet, and real FL was not tried.
- **Presets:** nobody has listened to a preset (the build machine has no sound card; the check is that a preset renders the same samples as Instrument Runaway for the same instrument, 100 of 100 tested through the plugin) and FL itself has not played one. A NES **DMC** preset cannot be played yet. A preset carries the way a game played its sample ("game voices") for **SNES** games only; Genesis game voices are not kept in a preset yet, and the **Audition** button plays the plain sample. A preset is only ever played with no ROM: a Presets chip and a running game cannot share an emulator (Load says so and changes nothing). The name field has no clipboard (type the name).
- **Test MIDI export:** nobody has listened to a replay (the check is that the ROM the plugin builds plays the converter's opcode streams frame by frame, and writes the same sound registers as a full build of the song by VRUN's own toolchain, on your 11 roster songs and on test songs). The song starts about one NES frame (17 ms) after FL's Play and always from its beginning (FL's song position is not followed); later tempo changes and pitch bends are not played (the game ignores them too); a song with only drums plays nothing in VRUN's converter and is refused; real FL has not been tried.
- **Record the music:** SNES and NES games (the other consoles are the next phase). NES: the DMC (sampled drums) is transcribed as notes but cannot be played by any engine yet; raw sound written straight to the DMC's level is not transcribed (said); the NES replays on the FIX chip whatever chip the game ran on (said when it differs); a NES note that changes duty is on the tracks of both duties (exact, but two tracks for one instrument). Nobody has heard a replay (the check is that the presets, played from the MIDI file the way FL plays notes, write the game's own pitch registers: every value exact or reported by the window) and FL has not imported a file or received live MIDI. Separate instances cannot replay effects between voices (pitch modulation, the shared echo, the noise clock); notes of one instrument that sound together share its channel's bend unless **Lanes** is ticked; voices already sounding when Record was pressed are not transcribed (press Record before the music starts). Not known until you try it in FL: whether FL tells a BrokenNes2 its channel's name (the SDK's context-info call; FL may answer with the mixer track's name, or nothing), and what FL's Replace hands the new instance (the log records both); the counter and the Link buttons do not depend on either.
- **Capture from FL:** the capture's clock is the samples FL renders since its Play (FL gave no song position in your log): a channel FL stops rendering for a while (Smart disable) would drift, and the window says so. A part on a channel whose root note you changed in FL (not C5) lands in another octave (FL does not tell a plugin). VRUN's engine plays no pitch bend (adding one to the game's engine is your decision). Real FL has not been tried: the stand-in host plays a song the way your FL log shows FL doing it.
- **BrokenDev** (the developer devkit for your homebrew projects) exists in the repository and is hidden in this build unless switched on for development.
- **Lite (browser) build:** not bundled in this hand-off. Tested by script (111 browser checks on all three consoles); the stock Genesis runs at about 2 to 2.4 times real time there and the Genesis on a NES picture chip below real time.
- **Not checked by any script:** sound through a real playback device, FL Studio itself (the plugin was driven by a stand-in host and by real mouse messages, never by FL), the installer's administrator prompt.
