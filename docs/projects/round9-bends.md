## 1. What the user asked for, and decided

"Add bends to VRUN's engine": slides and bends composed in FL Studio should play in the game exactly as BrokenNes2's Test MIDI export previews them. The game ROM's fixed bank is at its ceiling, so the cost was measured and shown before anything goes into the game build (phase 1, VRUN side, reported 2026-10-18; the game part waits for the user's decisions). Phase 2, this record's BrokenNes side: the converter copied again, the template rebuilt with the bend decoders, the frame-exact model and the checks extended, the facts say what the bends did. Standard MIDI pitch bend with RPN 0 (2 semitones when absent) so any FL or MIDI source works. The `capture` track (BrokenNes2 writes what FL plays as MIDI with bends + RPN 0 ranges) is concurrent; its record will be `docs/projects/round9-capture.md`.

## 2. The engine (VRUN side, phase 1)

| Piece | What |
|---|---|
| Opcodes | `$D1 lo hi` pitch: play period hi:lo now (a note-on at an exact period). `$D2 lo hi` slide: add hi.lo (signed 8.8, +-128 period units a frame) to the period every frame from the next one. One frame of the channel's one-opcode budget each; a note-on and the loop stop a slide. |
| Converter (`Bends.cs`) | Opt-in per song (`ConvertOptions.Bends`, CLI `--bends`, roster `"bends": true`). The note stream is built and retimed as before; bend opcodes go only into frames where the decoder idles (waits are split): **notes never move**, a song without bends gets the old bytes, bends are what is thinned. Held bends land exactly on floor(exact period) (the note table's rule: +2 held = the note 2 up); moving bends within 10 cents or half a frame of their own motion. Over 1,280 bytes: coarser tolerance, then held pitches only, then none (never fewer notes). The noise's bends are counted and ignored. Everything is logged and in `SongResult.Bends`. |
| Decoders | Bend variants of square 1, square 2 (plain and SFX-resync) and triangle, picked per channel from the converted streams (`"bend_decoders": "all"` for a template). 16.8 period + 8.8 slide in RAM (5 bytes a channel), the slide stepped before the wait check (low register every frame, high only when it changes: a pulse's high write restarts its waveform), cleared on a frame whose pointer is 0. |
| VRUN proofs | `converter/tests/run-identity.sh`: 1,511 files (11 roster + 1,500 random) byte-identical to `6c561f6` without `--bends`; with it, no file changes without a bend channel, and the 705 that change keep every note (volume, gate, noise equal over two loops). `convertertests bends`: 12 synthetic songs through a frame-exact model against the MIDI's own pitch curve, 4 broken-model controls caught. `tests/bend_rom_check.sh`: 6 one-song AudioPlayers on BrokenNes, the decoders' own APU writes (rebuilt from `--instr-trace`) equal the model in every NMI over two loops. |
| Cost (measured) | CPU +50 to +190 cycles a frame per bending channel (all three: 552 average / 1,194 max vs 216 / 618). ROM: a bend decoder is 190-210 bytes bigger, in its song's bank. Game: roster as committed = zero cost (identical generated files); bends on its 3 bending songs = builds, fixed bank 31 unchanged (1,777 free), -2.5 KB switchable, +15 B RAM; worst case (all 11 songs, bend decoders everywhere) builds, bank 31 unchanged, -9.4 KB switchable. |

## 4. Found on the way: a busy frame's NMI runs past the end of the emulator's frame

The AudioPlayer's NMI starts at vblank, near the end of `RunFrame` (which returns at the end of the last vblank line). With round 7's plain decoders the music was always written before that; with the bend decoders on three channels the decoders cost more, and on a busy frame (all channels decode; once a second the player also redraws its status line) the NMI is still writing the last channels (the noise, sometimes the triangle) when `RunFrame` returns. A latch read there (round 7's sample point, and the Workshop `--trace`) shows those registers one frame late. Measured in the `engine` check: 100 frames in all over 22 songs (about 45,000 frames), 0 to 17 a song; the Workshop instruction trace shows the CPU inside the decoder at the sample point, and the value one frame later. The values are right, the sample point is not: `Music/NmiLatch.cs` rebuilds the registers each NMI left from the APU write tap (a write in the first half of a frame belongs to the previous NMI), and every check that compares registers with a model or another ROM uses it. On the real machine and in the plugin's audio this is a write about 0.5 to 1 ms later in the frame on those frames; the model is frame-level and unaffected.

The same lag touches the player's position and loop counter (RAM, read when the frame ends; `pl_audio_post` updates them after the decoders): the `reference` check allows a sample one frame late there and counts it; any other difference fails.

## 6. Not tested (said plainly)

- **Nobody listened.** No sound card on the build machine: every claim is a register trace, a model or a count.
- **Real FL Studio:** its MIDI export's bend resolution and range (RPN 0 or not), FL's slide notes as exported, and a take of Capture from FL in real FL (the FL-faithful host's take is checked end to end: FL's pitch -> the file -> the converter -> the plugin's machine).
- **A gameplay song with bends in the shipped game:** none has `"bends": true` (the user's decision). Section 8 measured a test copy whose gameplay songs bend: the CPU and the frame timing, not the sound.
- **Square 2's bend decoder while a sound effect borrows the channel**: it ran in the test copy during combat and the SFX soak (CPU only); its registers after a sound effect were not compared with a model.
- **What one overrun frame does to the picture** (section 8): the main loop misses a frame; whether the NMI then uploads a half-updated sprite or HUD buffer was not checked.

## 7. Decisions taken here

- Bends always on in the plugin (no switch): a no-op without bends, proven per song.
- The template carries the bend decoders on all three tonal channels (any song can be patched in), format version 2; version 1 refused.
- Registers compared per NMI; the player's RAM position allowed a one-frame sample lag, counted.
- No new hook number (the `capture` track works in the same window): hook 611 gained a flag bit, hook 615 indexes 14-17.
- A take of Capture from FL plays its bends (the capture's fact says so, ranked with the slides, no longer a warning); the capture's `convert` check and `selftest` `engine` scenario now verify the take end to end.
- Found on the way: VRUN's converter stops a channel at ANY note-off, so where FL's notes overlap on one channel the earlier note's end cuts the newer one short (in the capture checks' take: the note that slides down an octave plays 2 frames, then 21+ silent frames, its slide unheard). This predates bends; the capture's fact said "the channel plays the newest" (true of BrokenNes2 only) and now says VRUN cuts it (warning colour, ranked high), and `capture-test` `convert` holds the ROM to it. Changing it (the capture ending an overlapped note where the next starts, or VRUN's converter ignoring a note-off of a key that no longer sounds) is the user's decision: the second changes the game's existing songs that overlap.
- The bends line puts what was lost first (bend frames thinned, `bends not played on <channel> (why)`), then where they play: the window cuts a long line at its end and the losses must stay visible.
- The checks find the VRUN tree by `BROKENNES_VRUN`, then `VRUN_ROOT` (the VRUN workspace's `nesdev-env.sh`), then BrokenDev's restored copy, which predates the merge: with that copy the `converter` and `template` checks fail by design (the copy here is newer than that VRUN).

## 8. The game with bending gameplay songs: frame headroom (the user's decision 4, "measure in gameplay first")

**Builds.** Both from VRUN `audio-bends` (= `6c561f6` + the bend engine), frozen in the workspace: `builds\2026-10-18_cputest_nobends` (the roster as committed) and `builds\2026-10-18_cputest_gameplay-bends` (think, level2, boss and baropen, the shop's song, given a continuous bend wave on the three MIDI channels VRUN plays on square 1, square 2 and the triangle, with `"bends": true`; the MIDIs are in its `midi\`). The wave (`engine/audio/tests/inject_bends.py`: +-40 cents, a 32-frame triangle) keeps a slide running on every frame a note sounds; the converter played it on all three channels of all four songs (up to 150 slides and 6-60 pitch steps a channel; think's square 1, which plays little, got pitch steps only; some channels at a 20-40 cent moving tolerance to stay under 1,280 bytes). Bank 31 unchanged (1,777 free).

**Method.** 17 of the game's own check scenes (busy combat in levels 0-5, the corruption detector's combat, level 2 combat, level 2's busiest rooms moving and firing, level 5's densest rooms with pickups, a whole-room sweep, the boss arena under HUD and heal-wrap stress, the shop reveal and the shop UAT, transitions, the SFX soak), run unchanged by Mesen with `tools/frame_headroom.lua` watching (`engine/audio/tests/gameplay_headroom.sh`, `headroom_compare.py`; committed on `audio-bends` as `3be2ecf`). Per frame: the main loop's spare cycles (from its call of `runtime_wait_nmi` to the NMI), an overrun (the NMI came while the main loop still worked), the NMI's length (entry to its RTI) and its `$2005` time. 69,612 frames per build; the two builds played the same game frame for frame (player, room, RNG, track) in 16 scenes and in the first 851 frames of the 17th.

- **The decoders' cost** (frames where both builds played the same game and the music ran, by song): the NMI grows by 250 cycles on an average think frame (median 209, 99th percentile 528, at most 919; 26,765 frames), level2 206 (179 / 528 / 999; 18,364), boss 204 (172 / 466 / 699; 1,599), the shop's song 257 (210 / 700 / 892; 7,853); the title song, not bent, 0 (4,835 frames: the measure isolates the bends). The table's NMI means are over each scene's music frames, title screens included. The decoders run after the vblank-critical writes, so the `$2005` time does not move for them (outside shop drawing, the two builds' `$2005` times differ by at most 17 cycles either way, from code placement).
- **Where it matters:** the game's two heaviest moments already run close to the frame's end without bends: a whole-room sweep (least spare 135 cycles; this run's bending frames there happened to be lighter) and heal wraps in the boss arena (least spare 210). With bends, that boss-arena frame overran by the NMI's extra 200 cycles: the main loop missed one frame (one frame of slowdown; the NMI, music included, still ran), and from frame 852 the two runs played different games (the scene's own check still passed: all 179 heal bursts granted).
- **A layout effect, not the decoders:** the bigger music data made NESFab place `shop_price` and `shop_write_digits5` in bank 0 instead of 3 and 10 (the same in a second build of each: reproducible), so every shop-drawing NMI writes `$2005` 78-81 cycles later (at most 2,064 of the 2,273-cycle budget in the shop scenes). In `audio_transition_check.lua`'s forced shop draw, which already writes late without bends (11 writes on the pre-render and first lines with rendering on), 18 land there.
- **The game as merged** (no song bends, `builds\2026-10-18_nes_bends`): the same NMI as before the merge (busy level 0 and boss heal wraps: means 2,574 and 2,419, the same maxima), no new overrun, the shop code where it was.

What this means for the user's decision to give a gameplay song bends: an average frame affords it easily; the sweep and the boss-arena heal wrap need a few hundred cycles found first (or the song's bends kept off those moments), and a build with the song's bends should be checked for where NESFab puts the shop code (`gameplay_headroom.sh` + `headroom_compare.py` do both in about 12 minutes).
